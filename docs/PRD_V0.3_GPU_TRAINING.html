01

背景、现状与证据

将历史事实、用户本机证据和下一阶段计划分别记录。

既有 Bone Atlas 已实现“PNG＋性别 → 质量复核 → 真实骨龄预测 → Grad-CAM → 人工意见”的研究闭环。当前模型为轻量 CNN，尚未达到原 PRD 的 MAE <6 个月目标。本次需求聚焦训练与模型集成升级。

事项当前证据状态与边界
既有模型与训练灰度 96×96、三层卷积、性别嵌入；20 轮 CPU 训练。最佳验证 MAE 18.7502 月，最后一轮为最佳。已有 未采用预训练骨干；最后一轮最优提示可研究训练日程，不证明延长训练一定改善。
原模型留出效果1,260 张：MAE 19.2524 月、RMSE 25.5958 月；3 张有限原始输出为负。效果未达目标 负值计入原始误差，应用拒绝展示为有效骨龄。
全量数据检查12,811 张 PNG 与表格匹配，0 解码异常；固定 10,091 / 1,260 / 1,260 分区。已有云端证据 用户本地完整图片／缓存尚未确认。
Windows 兼容检查用户终端截图：Windows 11、Python 3.14.0、torch 2.14.1+cpu；12 组图片／性别检查 passed，最大预测差异约 0.0000458 月。用户本机通过 覆盖旧模型预测与热力图；截图 holdout=null，未证明本机完成 1,260 张复测或 GPU 训练。
Linux 兼容检查Python 3.14.8 / torch 2.14.1 CPU；15 项测试无跳过；1,260 张回归 MAE 仍为 19.2524 月。已有报告 属于旧模型兼容性，不是新模型效果。
GPU 训练升级预训练 ResNet-50、CUDA、AMP、新预处理及相应推理／解释适配。待实施 显卡型号不等于 CUDA 环境已经可用。
版本关系V0.3 补充并更新 V0.2 中的模型开发、评估、集成和验收要求。V0.2 保留为历史需求；其中“未训练／仅抽查七张”等是当时状态。当前事实以本节及已有报告为准。本次交付只生成静态 PRD，不修改训练或应用业务代码，也不启动训练。
02

目标、范围与成功定义

目标本阶段要求通过条件
G-01 · 效果目标保留总体 MAE <6 个月的原门槛。冻结模型／预处理／评估协议后，在独立有标签评估中达到目标；报告总体、分层、样本数、置信区间和失败情况。未达标须如实标记。
G-02 · GPU 可训练在用户 RTX 4060 Laptop 上执行可恢复的真实训练与验证。CUDA 实际可用、梯度更新有效、有限 loss、训练和验证完成、显存及耗时有记录；启动脚本或检测显卡不单独算通过。
G-03 · 可复现实验分区、配置、日志、权重与逐样本预测可追溯。每个实验独立存储，可识别训练配置、阶段、随机种子、数据和环境；调参默认不读取留出集。
G-04 · 可集成与回滚候选模型可执行骨龄预测、原图坐标热力图及版本记录。新旧架构均有适配；候选完整验证后显式注册，失败候选不替换活动模型；旧版本与历史结果可保留、回滚。

P0 · 本轮必须规划

GPU 环境预检、完整数据路径、预训练骨干＋性别、版本化预处理、阶段训练、验证集选优、断点恢复、分层评估、模型注册／回滚、预测与 Grad-CAM 适配、文档与测试。

P1 / P2 · 后续独立研究

P1：更高分辨率、经验证手部裁剪、ROI 标注／检测、DICOM、可视化实验管理。P2：同患者时序、身高、成年结局和闭合时间窗。当前单张模型调参不能替代这些数据。

验收分开判定GPU 能运行、训练流程通过、模型效果达标、临床可用是四项不同结论。候选即使功能通过，MAE 未达 6 月时仍标为“研究候选／效果未达标”。本阶段不承诺医院使用有效性。

04

硬件、环境与资源约束

条件要求检查与处置
目标硬件NVIDIA GeForce RTX 4060 Laptop GPU，用户报告 7957MB，按约 8GB 规划。记录实际 GPU 名称、总／空闲显存、驱动、峰值显存；桌面及其他进程会占用余量。
Python 与依赖标准 64 位 Python 3.14；本机旧环境为 3.14.0。选择官方有对应 Windows wheel、互相兼容的 CUDA 版 PyTorch 与 torchvision；验证后单独锁定 GPU 训练依赖。具体组合待驱动预检后确定。
CUDA 可用性记录 nvidia-smi、PyTorch 构建 CUDA、torch.cuda.is_available() 与实际设备。以真实张量运算、前向／反向更新为最终预检；系统报告的 CUDA 支持版本不等于 PyTorch 使用的运行时。现 +cpu 构建不能使用 GPU。
环境隔离新建 GPU 训练虚拟环境，例如 .venv314-gpu，保留现有 CPU 运行环境。提供 PyCharm 解释器选择与 Windows 路径说明；不默认卸载旧环境，也不把 GPU 成功建立在关闭 TLS／校验上。
Windows 数据加载从 num_workers=0 起步，确认稳定后试验增加；入口满足 Windows 多进程启动要求。支持含空格／中文路径，文件句柄和工作进程独立；性能优化前先验证无重复／遗漏样本。
资源与耗时先短跑测量 step 时间、整轮估算、GPU 峰值、RAM 和磁盘占用。完整包不含约 10GB 数据；根据原图、缓存、临时文件和候选数检查空间。笔记本插电并使用稳定散热模式，耗时以实测为准。
ENV-01 · 环境验收请求 CUDA 训练而设备不可用时，应明确失败并给出诊断；不得静默转为 CPU 后仍报告“GPU 训练成功”。CPU 训练／推理作为显式独立模式。官方预编译 wheel 通常自带所需 CUDA 运行依赖，不将完整 CUDA Toolkit 作为默认必装条件。
05

数据准备、预处理与固定分区

编号需求验收要点
DATA-01使用完整 12,611 条有骨龄标签的原始图片及对应 CSV；200 张无标签图单独保留。显式指定本地数据路径；核对 ID、骨龄、性别、缺图、解码、重复和哈希。六张演示图片不能代替训练数据。无标签图不参与误差计算和模型选择。
DATA-02沿用已保存的源图片 ID 分区：训练 10,091、验证 1,260、留出 1,260，种子 20261022。从固定清单读取分区并核对哈希；改变分辨率／缓存实现时不得重新随机分区。重复／近重复候选保持同区；新增分组证据导致变化须建立新协议并说明可比性。
DATA-03从原始 PNG 生成 224 输入，保留宽高比，以填充达到正方形。不得把既有 96 缓存放大冒充高分辨率实验。记录原始尺寸、缩放、有效区域和填充变换；后续 384／512 也从原图生成并独立版本化。
DATA-04为预训练 ResNet 定义灰度转三通道和归一化协议。初始方案：同一灰度复制为 RGB 三通道，转 [0,1] 后使用所选 ImageNet 权重的归一化参数；标签仍为月，性别 M=1/F=0。训练、验证、推理和解释使用相同处理版本。
DATA-05训练增强、统计估计和采样只作用于训练分区。保留原图；先比较轻度亮度／对比度增强。小角度旋转／平移另立实验，检查指尖、腕部不被裁掉；验证与测试无随机训练增强。不默认镜像或强制左右侧统一。
DATA-06管理缓存、异常与数据限制。缓存含输入版本、源数据／分区哈希、尺寸与数据类型；避免整库 RGB 浮点张量常驻显存。每个排除有预定义理由并保留记录，不能按预测误差剔除难例。

06

训练功能需求与起步配置

本节是下一版需要开发的能力，参数是可验证的初始提案。当前脚本尚不支持其中的预训练骨干、CUDA 和 AMP。

配置项初始提案说明
模型与输入预训练 ResNet-50 ＋ 性别嵌入；224×224移除原分类头，池化图像特征后与性别特征融合为回归头；新架构标识与旧 CNN 分开。
预训练权重官方 ImageNet 权重；固定具体版本与校验值记录下载来源、标识和许可。下载失败应明确停止；不能随机初始化后仍标记“预训练”。
物理／有效 batch物理 batch=8，梯度累积=1，有效 batch=8显存有余量再独立尝试 16。OOM 时可改 4×2 或 2×4，记录变化与最后不足批次的损失缩放。
训练精度CUDA AMP；按实现使用梯度缩放记录实际精度和缩放状态，检查非有限 loss／梯度；导出和默认部署使用 CPU 可加载的权重。
阶段一冻结骨干，训练回归头约 3 轮；学习率 3e-4冻结参数时同时明确 BatchNorm 运行统计策略；预训练骨干不发生意外更新。
阶段二解冻微调；骨干 3e-5、回归头 3e-4可逐层解冻，但阶段、可训练层、参数组与学习率必须进入配置和日志。
优化器／衰减AdamW；weight_decay=5e-4作为初值；所有参数组及调度策略固定记录。小 batch 下先评估冻结 BatchNorm 统计的策略。
轮数／早停总上限 60 轮（含冻结阶段）；patience=10建议验证 MAE 改善 0.05 月才重置早停计数；每次最低验证 MAE 的权重仍单独保存。阈值是拟定配置，不是既有实测结论。
目标与损失保留月标签；初始归一化 (y−120)/60，SmoothL1 β=0.5与旧目标尺度一致；β=0.5 对应 30 月转折。后续单独比较 L1 或 β=0.1（6 月），不得把 β 本身当作精度承诺。
学习率日程明确阶段边界的余弦或验证集降率日程选一种并固定所有参数。更改总轮数会改变余弦轨迹，实验中标为训练日程变化。
编号功能需求完成判据
TRAIN-01配置驱动训练模型、数据／清单、尺寸、设备、AMP、阶段、batch／累积、学习率、损失、种子、输出目录均能配置；启动时校验组合并输出解析后的完整配置。
TRAIN-02独立运行与训练日志唯一 run_id；记录每轮训练 loss、无增强 eval 模式的训练 MAE、验证 MAE／分层偏差、阶段、各组 LR、时长、显存和有效 batch。归一化 loss 不与月 MAE 混为一谈。
TRAIN-03仅验证模式与最佳模型调参默认只用训练和验证集；按验证 MAE 选 checkpoint。日常训练不会自动读取留出集或更新活动模型。
TRAIN-04中断、断点恢复与导出区分 best、latest 和仅推理导出；恢复必要的模型、优化器、调度器、AMP、阶段／轮数、早停计数和随机状态。恢复时核对配置与数据版本，变更配置应新建运行。
TRAIN-05OOM／数值错误处置异常有明确状态、发生位置和最后有效 checkpoint。减 batch／累积须显式记录并从有效点恢复，不在残留梯度上继续。不得静默降低分辨率或产生“成功”记录；非有限结果不得注册。
TRAIN-06随机性与可复现保存 Python、NumPy、PyTorch、CUDA 随机种子与后端确定性设置、版本和设备；记录不可避免的非确定性。不同训练种子的模型不要求逐像素完全相同。
8GB 显存的工程约束先验证完整训练／验证批次与参数更新，再扩大实验。显存受分辨率、batch、优化器状态、其他进程和解释梯度影响；不能仅根据“4060”保证 batch=16 或 384／512 能运行。当前 GPU 依赖和参数尚未在用户显卡上验证。

7.1 最小可解释实验序列

7.2 训练选择与最终检验

  1. 先冻结数据清单、分区、输入范围、标签标准／单位、指标和异常处理规则。若参考标准尚未核实，明确研究限制。
  2. 学习率、轮数、尺寸、损失、增强、采样及模型选择只根据训练／验证信息。最终候选可用多个固定种子检查验证表现，记录所有尝试。
  3. 冻结最终配置、权重 SHA-256、代码版本、预处理与解释方法，独立执行最终评估，结果落盘后不得静默改模型。
  4. 既有留出集的总体和分层结果已被观察；若进一步根据这些结果改方案，应明确其探索用途，并新增独立最终／外部检验。不能通过换随机种子或把已用于调参的样本重新命名为测试集获得“独立”结论。

编号后续修改验收要求
